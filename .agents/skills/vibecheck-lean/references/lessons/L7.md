# L7 · Make illegal states impossible

> So far, proofs sat next to the code. Now they go inside the data. A value that would break a rule can't even be built, so no later code (yours, a teammate's, an agent's) will ever see one.

*About 10 minutes · practice file `Learn/L7_Invariants.lean`*

## A type that carries a proof

```lean
structure Counter (limit : Nat) where
  value : Nat
  ok : value ≤ limit
```

```tree spans=0:9,10:31,32:37
structure Counter (limit : Nat) where
│         │                     └─ the fields follow
│         └─ one counter type per limit: `Counter 10`, `Counter 3`, …
└─ a record type with named fields
```

```tree spans=2:7,10:13
  value : Nat
  │       └─ of type `Nat`
  └─ an ordinary field
```

```tree spans=2:4,7:20
  ok : value ≤ limit
  │    └─ …whose content is a proof that `value ≤ limit`
  └─ a second field…
```

## Building one

```lean
def Counter.zero (limit : Nat) : Counter limit := ⟨0, Nat.zero_le _⟩
```

```tree spans=4:16,50:53,54:68
def Counter.zero (limit : Nat) : Counter limit := ⟨0, Nat.zero_le _⟩
    │                                             │   └─ …then `ok`: a library fact, 0 ≤ anything
    │                                             └─ build the structure: first `value`…
    └─ a function in the `Counter` family
```

Type the angle brackets `⟨` and `⟩` as `\<` and `\>`. The `_` asks Lean to fill in the obvious argument, here `limit`.

## Changing one safely

```lean
def Counter.incr (c : Counter limit) : Counter limit :=
  if h : c.value < limit then ⟨c.value + 1, by omega⟩ else c

#eval (Counter.zero 2).incr.incr.incr.value   -- 2
```

```tree spans=2:8,9:24,30:53,54:60
  if h : c.value < limit then ⟨c.value + 1, by omega⟩ else c
  │      │                    │                       └─ at the limit: unchanged
  │      │                    └─ a new counter: the value, and a proof, using `h`
  │      └─ …the condition
  └─ an `if` that names its condition `h`…
```

Inside `by omega`, the Lean panel shows exactly what the new counter has to satisfy:

```goal
limit : Nat
c : Counter limit
h : c.value < limit
⊢ c.value + 1 ≤ limit
```

`c.incr` is shorthand for `Counter.incr c`, so `.incr.incr.incr` increments three times. The result stops at 2: the counter saturates rather than breaking its limit.

## Using the rule a value carries

Every counter carries its own proof, `c.ok`. To use it, put it above the line with `have`:

```lean
theorem Counter.value_le (c : Counter limit) : c.value ≤ limit + 1 := by
  have := c.ok
  omega
```

```tree spans=2:6,7:14
  have := c.ok
  │    └─ …namely this counter's proof that `c.value ≤ limit`
  └─ add a fact above the line…
```

```lean fails
theorem Counter.value_le' (c : Counter limit) : c.value ≤ limit + 1 := by
  omega
-- Lean says: omega could not prove the goal
-- omega only sees what's above the line, and `c.ok` isn't there until you put it there.
```

## Where it stops working

```lean fails
def Counter.incrBad (c : Counter limit) : Counter limit :=
  ⟨c.value + 1, by omega⟩
-- Lean says: omega could not prove the goal
-- At the limit, value + 1 would break the rule, so Lean refuses to build this counter. That's the whole design: a broken counter isn't a runtime error, it's code that doesn't compile.
```

## Rule of thumb

| You want | Write |
| --- | --- |
| a value that always obeys a rule | a `structure` with a proof field |
| to build one | `⟨fields…, proof⟩`, the proof usually `by omega` |
| to use the rule a value carries | `have := c.ok`, then `omega` |
| a branch that knows its condition | `if h : cond then … else …` |

## Check yourself

1. Why can't any function return a `Counter 5` whose value is 6?
   Answer: Building it needs a proof of `6 ≤ 5`, and there is none.
2. What does the `h` in `if h :` give you?
   Answer: The branch condition, as a hypothesis the proof inside the branch can use.
3. Why did `omega` fail on `value_le'`?
   Answer: It only uses facts above the line, and `c.ok` wasn't there.
