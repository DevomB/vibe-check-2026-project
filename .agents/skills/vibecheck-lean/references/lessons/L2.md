# L2 · Facts about every input

> A test checks `double 3`. A proof checks every `n`, including the ones no test will ever try. That is the step from testing to verification, and here it takes two tactics.

*About 10 minutes · practice file `Learn/L2_Unfold.lean`*

## The statement

```lean
def double (n : Nat) : Nat := n + n

theorem double_ge (n : Nat) : n ≤ double n := by
  unfold double
  omega
```

```tree spans=0:7,8:17,18:27,30:42,46:48
theorem double_ge (n : Nat) : n ≤ double n := by
│       │         │           │               └─ proof steps follow, one per line
│       │         │           └─ the statement (type `≤` as `\le`)
│       │         └─ for any whole number `n`
│       └─ its name
└─ a fact with a name
```

`rfl` and `decide` can't help here: there are infinitely many `n`, and `double n` can't be computed without knowing `n`. So instead of computing, the proof reasons.

## Watch the goal change

Put the cursor right after `by`. The Lean panel shows what's left to prove:

```goal
n : Nat
⊢ n ≤ double n
```

Above the line is what you have: here, some number `n`. After `⊢` is what you must prove. Every tactic changes this picture.

```tree spans=2:8,9:15
  unfold double
  │      └─ which name
  └─ replace a name with its definition
```

```goal
n : Nat
⊢ n ≤ n + n
```

Now the goal is plain arithmetic, and **`omega`** proves it for every `n` at once. `omega` handles `+`, `-`, `=`, `<` and `≤` over `Nat` and `Int`, plus multiplying, dividing or taking `%` by a fixed number. When the panel says **No goals**, the proof is finished.

## Using a hypothesis

Sometimes the fact you need arrives as an input. Here `h` is a promise that `double a = 10`:

```lean
example (a : Nat) (h : double a = 10) : a = 5 := by
  unfold double at h
  omega
```

```tree spans=2:15,16:20
  unfold double at h
  │             └─ …but inside the hypothesis `h`, not the goal
  └─ same as before…
```

```goal
a : Nat
h : a + a = 10
⊢ a = 5
```

`omega` uses everything above the line, so from `a + a = 10` it concludes `a = 5`.

## Where it stops working

```lean fails
theorem double_ge' (n : Nat) : n ≤ double n := by
  omega
-- Lean says: omega could not prove the goal
-- omega doesn't look inside definitions. It treats `double n` as an unknown number, and an unknown number could be smaller than n. Unfold first.
```

```lean fails
example (a b : Nat) : a * b = b * a := by
  omega
-- Lean says: omega could not prove the goal
-- True, but omega can't multiply two unknowns together. That's a job for a library lemma, below.
```

```lean
example (a b : Nat) : a * b = b * a := Nat.mul_comm a b
```

`Nat.mul_comm` is a theorem from Lean's library, used like a function: give it `a` and `b`, get the fact. When you need a fact like this, search for it on [Loogle](https://loogle.lean-lang.org) by its shape, `_ * _ = _ * _`, or type `exact?` in the proof and let Lean search.

One trap that isn't an error:

```lean
example : (3 : Nat) - 5 = 0 := by decide
```

Subtraction on `Nat` stops at zero, because there are no negative whole numbers. `(3 : Nat)` tells Lean which type `3` has. This is why a `Nat` price can't go negative, and why code that needs negative numbers uses `Int`.

## Rule of thumb

1. `unfold` your function, so the goal is only arithmetic.
2. `omega` to finish.
3. If `omega` fails, read the goal: is a function name still there, or are two unknowns multiplied?

## Check yourself

1. In the Lean panel, what's the difference between the lines above `⊢` and the line after it?
   Answer: Above is what you have: inputs and hypotheses. After `⊢` is what you still need to prove.
2. Why did `omega` fail on `n ≤ double n` without `unfold`?
   Answer: It treats `double n` as an unknown number; it never looks inside definitions.
3. What is `5 - 8` as a `Nat`?
   Answer: `0`. Subtraction on `Nat` stops at zero.
