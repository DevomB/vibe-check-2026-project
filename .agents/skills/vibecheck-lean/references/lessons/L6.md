# L6 · Loops

> Most production code isn't recursive: it has variables and `for` loops. Lean can write that style too, and prove it, as long as you can say one thing: what stays true while the loop runs.

*About 15 minutes · practice file `Learn/L6_Loops.lean`*

## Imperative code in Lean

```lean
import Std.Tactic.Do
open Std.Do

def mySum (l : Array Nat) : Nat := Id.run do
  let mut out := 0
  for i in l do
    out := out + i
  return out

#eval mySum #[3, 4, 5]   -- 12
```

## The invariant: what stays true

```text
items seen      out    sum of items seen = out?
[]               0      0 = 0     ✓
[3]              3      3 = 3     ✓
[3, 4]           7      7 = 7     ✓
[3, 4, 5]       12     12 = 12    ✓   loop done, so out = sum of l
```

"`out` equals the sum of the items seen so far" is true on every row. That sentence is the **loop invariant**. It holds before the loop, each pass keeps it true, and at the end it gives you the answer. Once you have it, the rest of the proof is mechanical.

## The proof

```lean
theorem mySum_correct (l : Array Nat) : mySum l = l.sum := by
  generalize h : mySum l = x
  apply Id.of_wp_run_eq h
  mvcgen invariants
  · ⇓⟨xs, out⟩ => ⌜xs.prefix.sum = out⌝
  with grind
```

The first two lines are the same for every `Id.run do` function: they hand the code to the verifier. Copy them as they are.

```tree spans=2:8,9:19
  mvcgen invariants
  │      └─ the loop invariants follow, one per loop
  └─ turn the code into a list of facts to check
```

```tree spans=2:3,4:17,18:39
  · ⇓⟨xs, out⟩ => ⌜xs.prefix.sum = out⌝
  │ │             └─ the sentence from the table; `xs.prefix` is the items seen so far
  │ └─ at any point: `xs` is the loop's progress, `out` the variable
  └─ the invariant for this loop
```

```tree spans=2:12
  with grind
  └─ prove every one of those facts with `grind`
```

Lean 4.35 prints a warning that `mvcgen` is deprecated in favour of `vcgen`. Ignore it: `vcgen` is still experimental and fails on examples like this one.

## Where it stops working

```lean fails
theorem mySum_correct' (l : Array Nat) : mySum l = l.sum := by
  generalize h : mySum l = x
  apply Id.of_wp_run_eq h
  mvcgen invariants
  · ⇓⟨xs, out⟩ => ⌜out ≤ xs.prefix.sum⌝
  with grind
-- Lean says: `grind` failed
-- This invariant is true, but too weak. At the end it only tells you out ≤ l.sum, and the theorem needs equality. An invariant must be strong enough to give you the result when the loop finishes.
```

## Rule of thumb

1. Trace the loop on a small input, in a table like the one above.
2. Find the sentence that's true on every row: the variable equals, or is bounded by, something about the items seen so far.
3. Write it with `xs.prefix` and let `mvcgen … with grind` do the rest.
4. If it fails, check whether the invariant gives the result at the end.

## Check yourself

1. What is `xs.prefix` in the invariant?
   Answer: The items the loop has already processed.
2. The invariant `out ≤ xs.prefix.sum` is true. Why does the proof fail anyway?
   Answer: At the end it only gives `out ≤ l.sum`, and the theorem needs `out = l.sum`.
