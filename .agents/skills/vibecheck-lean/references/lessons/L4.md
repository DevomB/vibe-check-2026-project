# L4 · Recursion and induction

> Lists, trees, logs and histories have no fixed size. A recursive function handles any size by handling one shape at a time, and its proof does the same. That proof technique is induction.

*About 10 minutes · practice file `Learn/L4_Induction.lean`*

## A recursive function

```lean
def len : List α → Nat
  | [] => 0
  | _ :: xs => 1 + len xs

#eval len [5, 6, 7]   -- 3
```

```tree spans=4:7,10:16,17:22
def len : List α → Nat
    │     │      └─ …to a `Nat`: `A → B` is the type of a function
    │     └─ a list whose items have some type `α` (any type)
    └─ the length of a list, written ourselves
```

```tree spans=2:3,4:6,7:11
  | [] => 0
  │ │  └─ …has length 0
  │ └─ the empty list…
  └─ one line per shape of list
```

```tree spans=4:11,15:25
  | _ :: xs => 1 + len xs
    │          └─ one, plus the length of the rest: the recursive call
    └─ a first item (`_`: unnamed, unused) in front of the rest, `xs`
```

`[5, 6, 7]` is shorthand for `5 :: 6 :: 7 :: []`, so every list is either empty or an item in front of a shorter list. `len` follows that shape:

```text
len [5, 6, 7]
→ 1 + len [6, 7]
→ 1 + (1 + len [7])
→ 1 + (1 + (1 + len []))
→ 1 + (1 + (1 + 0))
→ 3
```

## The proof has the same shape

`++` joins two lists. Joining them adds their lengths:

```lean
theorem len_append (xs ys : List α) : len (xs ++ ys) = len xs + len ys := by
  induction xs with
  | nil => simp [len]
  | cons x xs ih => simp [len, ih]; omega
```

```tree spans=2:14,15:19
  induction xs with
  │            └─ the cases follow
  └─ prove it for every list `xs`, one shape at a time
```

```tree spans=4:7,11:21
  | nil => simp [len]
    │      └─ simplify, unfolding `len`
    └─ case 1: `xs` is the empty list
```

```tree spans=4:13,14:16,20:34,36:41
  | cons x xs ih => simp [len, ih]; omega
    │         │     │               └─ tidy the arithmetic
    │         │     └─ unfold `len` one step, then rewrite with `ih`
    │         └─ the induction hypothesis: the fact already holds for `xs`
    └─ case 2: the list is `x :: xs`
```

The two goals Lean hands you:

```goal
case nil
α : Type u_1
ys : List α
⊢ len ([] ++ ys) = len [] + len ys
```

```goal
case cons
α : Type u_1
ys : List α
x : α
xs : List α
ih : len (xs ++ ys) = len xs + len ys
⊢ len (x :: xs ++ ys) = len (x :: xs) + len ys
```

Think of induction as a loop for proofs. Prove the empty case. Then show that if the fact holds for `xs`, it also holds for `x :: xs`. Every list is built from `[]` by adding one item at a time, so those two steps cover every list. `ih` is the "it holds for `xs`" part, handed to you for free.

## Where it stops working

```lean fails
theorem len_append' (xs ys : List α) : len (xs ++ ys) = len xs + len ys := by
  simp [len]
-- Lean says: `simp` made no progress
-- With `xs` unknown, simp can't tell which line of `len` applies, so it can't unfold anything. Induction splits `xs` into its two shapes first.
```

## Rule of thumb

1. A function defined by `|` cases on a list means `induction` on that list.
2. `nil` case: usually `simp [f]`.
3. `cons` case: `simp [f, ih]`, then `omega` if arithmetic is left over.

## Check yourself

1. In the `cons` case, what does `ih` say?
   Answer: The statement already holds for the shorter list `xs`.
2. Why does `simp [len]` alone fail?
   Answer: It can't unfold `len` on an unknown list, because it doesn't know which case applies.
3. Why do the `nil` and `cons` cases together cover every list?
   Answer: Every list is `[]` or an item in front of a shorter list.
