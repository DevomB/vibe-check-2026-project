# L1 · Programs, and facts you can compute

> Lean is a programming language before it is a proof checker. In ten minutes you'll write a function, run it, prove a fact about it, and see exactly where the simplest proofs stop working.

*About 10 minutes · practice file `Learn/L1_Programs.lean`*

## A function, piece by piece

```lean
def double (n : Nat) : Nat := n + n
```

```tree spans=0:3,4:10,11:20,21:26,27:29,30:35
def double (n : Nat) : Nat := n + n
│   │      │         │     │  └─ the body; its value is the result, no `return` needed
│   │      │         │     └─ "is defined as"
│   │      │         └─ what comes back: also a `Nat`
│   │      └─ one input, `n`, a whole number (`Nat`)
│   └─ its name
└─ define something
```

`Nat` is the type of whole numbers: 0, 1, 2, and so on, never negative. Every input and every result has a type, and Lean checks all of them before anything runs.

## Run it

```lean
#eval double 21   -- 42
```

```tree spans=0:5,6:15,18:23
#eval double 21   -- 42
│     │           └─ a comment; Lean ignores everything after `--`
│     └─ call `double` on 21: no parentheses, no commas
└─ run this and print the result
```

Here is the shape Lean reads, and how it gets to 42:

```text
Function application
├── function: double
└── argument: 21 : Nat

double 21
→ 21 + 21     put 21 where n was
→ 42          add
```

## Prove a fact by computing

```lean
example : double 3 = 6 := rfl
```

```tree spans=0:7,10:22,23:25,26:29
example : double 3 = 6 := rfl
│         │            │  └─ the proof: compute both sides, check they match
│         │            └─ "and here is the proof"
│         └─ the statement
└─ a fact to prove, with no name
```

**`rfl`** is short for *reflexivity*: everything equals itself. Lean computes both sides (`double 3` becomes `3 + 3`, then `6`) and checks that what's left is `6 = 6`. If it is, the proof is done.

The same fact again, this time with a name and a tactic:

```lean
theorem double_three : double 3 = 6 := by decide
```

```tree spans=0:7,8:20,23:35,39:41,42:48
theorem double_three : double 3 = 6 := by decide
│       │              │               │  └─ the one step: run the check
│       │              │               └─ tactic mode: steps follow, not a finished proof
│       │              └─ the statement
│       └─ the name, so you can use it later
└─ a fact with a name
```

**`decide`** runs a yes/no check that Lean knows how to compute, and accepts the proof when the answer is yes. It covers more than equations:

```lean
def isZero (n : Nat) : Bool := n == 0

example : isZero 4 = false := by decide
example : double 3 ≠ 7 := by decide
example : 3 < 9 := by decide
example : ∀ n, n < 5 → n * n < 25 := by decide
```

```tree spans=10:14,15:22,23:33,40:46
example : ∀ n, n < 5 → n * n < 25 := by decide
          │    │       │                └─ tries n = 0, 1, 2, 3 and 4
          │    │       └─ "…its square is below 25"
          │    └─ "…below 5, it follows that…"
          └─ "for every n…"
```

`Bool` is `true` or `false`, and `==` compares. **`by`** switches from "here is the finished proof" to "here are steps that build it". Some names, like `rfl`, work both ways; `decide` and every tactic in later levels only work after `by`.

## Where they stop working

Each of these is rejected. The error is Lean telling you which rule you broke.

```lean fails
example : double 3 = 7 := rfl
-- Lean says: Type mismatch
-- Both sides compute, to 6 and 7, and they differ. The claim is false, and Lean will not prove a false claim.
```

```lean fails
example : 3 < 9 := rfl
-- Lean says: Type mismatch
-- True, but not an equation. `rfl` only proves `a = b`; `decide` handles `<`.
```

```lean fails
example (n : Nat) : double n = 2 * n := rfl
-- Lean says: Type mismatch
-- True for every n, but n is unknown, so neither side computes to a number. Facts about every input are L2.
```

```lean fails
example (n : Nat) : double n = 2 * n := by decide
-- Lean says: Expected type must not contain free variables
-- `decide` would have to try every n, and there are infinitely many. A free variable is an unknown like n.
```

## Rule of thumb

| You want to prove | Use |
| --- | --- |
| an equation between specific values, like `double 3 = 6` | `rfl` |
| any other yes/no fact about specific values: `3 < 9`, `x ≠ y`, "every n below 5" | `decide` |
| anything about an unknown `n` | neither; that's L2 |

## Check yourself

1. What does Lean do when you write `rfl`?
   Answer: It computes both sides and checks that they end up identical.
2. Why does `rfl` reject `3 < 9`, even though it's true?
   Answer: `rfl` only proves equations. `decide` proves `3 < 9`.
3. Why can't `decide` prove `double n = 2 * n`?
   Answer: It would have to check infinitely many values of `n`.
